# SPEC — проект XKALMAR (xkalmar-party)

## Что это
Сайт сети квест-шоу для детей в Ростове-на-Дону. Мультистраничник:
главная + страницы поводов. На каждой — свой контент + один калькулятор +
одна форма. Цель: посетитель за минуту понимает формат и цену и
оставляет заявку. Основной канал трафика — органика из поиска.

## Стек (актуально)
- Astro 7.4.2, Vite 8.3.5, Node >= 22.23.4, TypeScript strict
- Без UI-фреймворков, без Tailwind.
- В <script> внутри .astro файлов обязательно // @ts-nocheck в начале скрипта.
- Деплой: Cloudflare Pages. Домен: xkalmar.com на reg.ru.

## Принятые решения: Модель «Корзина» (актуально, v7.31)
1. Бар УДАЛЁН. Два состояния: Пилл (закрытая корзина: счётчик позиций +
   цена + dirty-точка ВНУТРИ пилла, без обводки, с пульсом) и Шторка
   (открытая корзина: список, удаление, «Очистить», кнопка действия, «Итого»).
   Пилл на всех экранах, включая десктоп. Тап по пиллу открывает шторку.
   Пилл виден только при выбранном пакете/формате.
2. Тост показывается после КАЖДОГО реального переноса/обновления (8 сек).
   Первый перенос — всегда реальный (тост + «Добавлено ✓»).
   Кнопка «Перейти к заявке» (состав не менялся) — только плавный скролл
   к форме.
3. Карточка пакета = radio. Бейдж «Выбрано ✓» — справа в строке названия
   (drc-card__namerow), карточки компактные, без toprow. У Оптимального
   бейдж «Выбирают чаще всего» и «Выбрано ✓» делят один слот: до выбора —
   «Выбирают чаще всего», после — «Выбрано ✓». Клик выбирает тариф
   и скроллит к шагам. «Подробнее» только раскрывает описание.
4. Повторный клик по выбранной карточке пакета СНИМАЕТ выбор (unsetPack):
   шаги скрываются, пилл исчезает, состав заявки (snapshot) НЕ очищается —
   отмена выбора это не «очистить корзину».
5. Ярмарка — единая модель «две плашки» (детали в разделе «Цены»).
6. Разбор пакета: в Максимальном меню под ключ (1 000 × дети), шары (3 500),
   фото (6 000), торт (7 000) — снимаемые позиции с пометкой «в пакете»
   в колонке цены (не отдельным элементом, рвущим строку). Видеосъёмка —
   платный доп во всех тарифах, пометки нет.
7. После снятия любой пакетной позиции тариф становится
   «Свой формат (на базе «X»)» с пересчётом цены; надпись в шаге «Программа»
   обновляется мгновенно (syncProgramUI внутри recalcAll); появляется
   кнопка «вернуть как в пакете».
8. Основная программа обязательна: отдельно ярмарка не продаётся; гвард —
   кнопка добавления блокируется при итоге ниже 15 000 ₽.
9. Выбор ярмарки хранится в state.extSel с тремя состояниями:
   undefined (не трогал — дефолт пакета), число (выбрано), null (снято
   пользователем). Восстановление из localStorage различает все три.
10. Глоссарий в шаге «Программа» (квест-шоу / ярмарка / банкет) —
    всегда видимый.
11. Состояния кнопки переноса: до первого переноса — «Добавить к заявке»;
    после переноса без изменений — «Перейти к заявке»; состав изменился
    до отправки формы — «Перенести изменения»; после успешной отправки формы
    (window.DR_CALC.sent = true, сохраняется в localStorage) и нового
    изменения — «Обновить заявку».
12. В форме заявки при dirty — бирюзовый статус-бокс: текст статуса
    («Расчёт изменился — состав заявки устарел» / «Состав изменился после
    отправки заявки») и кнопка «↻ Перенести изменения / Обновить заявку».
    Бокс управляется ТОЛЬКО style.display (не атрибутом hidden — конфликт
    с [hidden] !important). На мобиле бокс складывается в столбик,
    кнопка на всю ширину.
13. Шаги калькулятора пронумерованы: «1 · Программа» … «5 · Дополнительные
    услуги» — это «подпись» калькулятора, маршрут для мамы.
14. Панель «Состав заявки» в форме: перерисовка только при реальном
    изменении данных (renderKey-гвард), анимация цены — мягкая подсветка
    (opacity), не scale; свёрнутость на мобиле не сбрасывается при
    обновлениях; ширина панели = ширине колонки (без width: 100%,
    на мобиле align-items: stretch в flex-колонке).
15. Канон строк состава заявки (единственный источник — TARIFFS.includes):
    «Квест-шоу, 3 ведущих-актёра · 1,5 ч», «Подвижные игры с призами ·
    30 мин», «Праздничный стол · своя еда · 30 мин». Формат «суть ·
    длительность». Мобилка и десктоп показывают одно и то же.

## Лексика бренда
- Название формата — «квест-шоу» (не «квест» и не «квест-приключение»)
  во всех текстах, подсказках и глоссарии.
- «Ведущие-актёры», НЕ «аниматоры». Сотрудники — актёры, работающие по
  единому сценарию (пример: Степан, фронтмен «Игры в кальмара»).
- «Команда из 3 ведущих-актёров» — единая формулировка во всех пакетах;
  «ведут те же актёры» — только в глоссарии (свойство формата, не пакета).
- В Максимальном расширенная — ЯРМАРКА ИГР (подвижные игры + мафия под
  конец), а не «сценарий квеста». Конструкцию «расширенный сценарий»
  в текстах не использовать.
- «Стена-кидалка» — один объект, не две позиции («интерактивная стена»
  и «кидалка» отдельно не упоминать).
- Мама, бронирующая впервые, должна понимать текст без жаргона.
- Информация между пакетами не расходится: новый пакет = предыдущий +
  что-то ещё (Популярный → Оптимальный: +час игр, +банкет под ключ →
  Максимальный: +фото, шары, торт, подарки).

## Правила для ИИ-агента
1. Не переписывать логику расчёта цен без явного запроса.
   В calculate() всё выверено вручную. После любой правки расчёта —
   прогнать таблицу «Контрольные цены».
2. Не возвращать устаревшие элементы (правую колонку «Ваш тариф»,
   вкладки «Пакеты/Свой формат», кнопку «Выбрать» на карточках, бар,
   absolute-бейджи и toprow на карточках, опции «без ярмарки» в ярмарке,
   «Банкет под ключ 6 000 ₽» как фиксированную позицию).
3. Все скрипты в .astro должны начинаться с // @ts-nocheck.
4. Сначала план (какие файлы, что меняем), ждать «ок», потом код.
5. В конце ответа — чеклист проверки руками.
6. Руководствуйся здравым смыслом и привычными паттернами современных
   интерфейсов (агрегаторы, маркетплейсы, Яндекс). Если буква инструкции
   конфликтует со здравым смыслом — не выдумывай, поставь // FIXME-REVIEW
   и продолжай по букве.
7. Для radio-групп с «клик по выбранному снимает выбор»: признак повторного
   клика — совпадение value кликнутого элемента с текущим значением
   состояния (String(curValue) === inp.value), НЕ inp.checked — браузер
   обновляет checked до выполнения click-обработчиков. После изменения
   состояния обязательно перерисовывать соответствующий блок
   (syncExt/sync*) — иначе хинты и пометки не обновятся.
8. Атрибут hidden и инлайн style.display не смешивать: для элементов,
   которыми управляет JS через style.display, в разметке ставить
   style="display:none", не hidden.
9. Frontmatter .astro-файлов: ровно две линии --- на собственных строках,
   перед первой ничего нет; комментарии внутри — одна строка, чтобы
   не «вытекали» на страницу.
