# XKALMAR Visual QA — навык визуального контроля качества

## Назначение
Постоянный визуальный контроль сайта XKALMAR при любой правке,
затрагивающей внешний вид, стили, компоненты UI или адаптивность.
Главный принцип: **сначала живой браузер, потом скриншоты** — скриншоты
это доказательства и материал для сравнения с концептом, а не замена
проверки. Проверяют сайт роли design-lead (приёмка против концепта)
и live-qa (полный прогон).

## 1. Подготовка
1. Убедись, что dev-сервер запущен: `astro dev status`; если нет —
   `astro dev --background` (localhost:4321).
2. Браузер: browser_action (или Playwright MCP, если подключён).

## 2. Живая проверка (обязательна)
Порядок: мобильная ширина **390** — главная; затем **1440**; выборочно
360 / 768 / 1024 (resize). Проверь руками:
- первый экран: за 5 секунд понятно, что, где, сколько, как заказать;
- прокрутка всей страницы;
- все кнопки и ссылки: tel:, WhatsApp, Telegram, ВК;
- модалки: открыть/закрыть, Esc, прокрутка фона;
- галерея: листание, свайп, клавиатура, лайтбокс, загрузка картинок;
- видео: открытие и воспроизведение;
- калькулятор: контрольные цены из SPEC-business.md (гейт Г4);
- форма заявки: валидация, ошибки, отправка, успех, согласие на ПД;
- ContactFab;
- состояния hover / focus / active / disabled;
- анимации и prefers-reduced-motion;
- консоль: 0 ошибок; сеть: нет 404 и битых ресурсов.

## 3. Скриншоты (после живой проверки)
- Полные скриншоты по ширина́м: `full-<width>px.png`.
- Скриншоты изменённых секций — для сравнения «до/после» и для
  STATUS.md.
- Папки: docs/qa/assets/ (QA), docs/concepts/<дата>/ (концепты),
  docs/screenshots/ (базовая линия «до», не перезаписывать).
- Помощник: docs/screenshots/take-shots.cjs.

## 4. Типографика и сетки
- Заголовки h1–h2: иерархия, контраст (подзаголовок ≠ основной текст).
- Текст: line-height ≥ 1.5; на тёмном фоне не чистый белый (rgba).
- Карточки: равные отступы, выравнивание по высоте, без наложений.
- Нет горизонтального скролла ни на одной ширине.

## 5. Критерий
Сайт выглядит так, что хочется заскринить и отправить другу; с первого
взгляда понятно, что предлагают, сколько стоит и как заказать.
Результат докладывается: design-lead — приёмка против концепта,
live-qa — отчёт docs/qa/live-<дата>.md с P0/P1/P2.
