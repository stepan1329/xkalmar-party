# XKALMAR Visual QA — Навык визуального контроля качества

## Назначение
Этот навык обеспечивает постоянный визуальный контроль сайта XKALMAR при любой правке, затрагивающей внешний вид, стили, компоненты UI или адаптивность.

## Когда применять
- Любая правка CSS, стилей, классов в `.astro` файлах
- Добавление или изменение секций, карточек, кнопок, форм
- Работа с галереей, видео, модальными окнами, лайтбоксом
- Любые изменения, видимые пользователю на экране
- Запросы на проверку визуального качества перед деплоем

## Процедура визуального аудита

### 1. Подготовка
1. Убедись, что `astro dev` запущен в фоне: `astro dev status`
2. Если нет — запусти: `astro dev --background`
3. Определи корневой URL: `http://localhost:4321`

### 2. Скриншоты по разрешениям
Сделай скриншоты главной страницы (`/`) на всех ключевых разрешениях:
- **1440px** — десктоп
- **1024px** — планшет
- **768px** — планшет (вертикальный)
- **390px** — iPhone 14/15 Pro
- **360px** — узкие Android

Для каждого разрешения:
- Измени размер окна браузера инструментом resize на нужную ширину
- Сделай полный (full-page) скриншот страницы
- Сохрани с префиксом `full-<width>px.png` (например `full-1440px.png`)

### 3. Скриншоты ключевых секций
На разрешении 1440px сделай отдельные скриншоты каждой секции:
- Hero (`section.hero`)
- Формат (`section.format`)
- FAQ (`section.faq`)
- Калькулятор (`section.drc`)
- Timeline (`section.timeline`)
- Ярмарка игр (`section.yamarka`)
- Площадка (`section.hallway`)
- Features (`section.features`)
- Отзывы (`section.reviews`)
- Галерея (`section.gallery`)
- Форма заявки (`#zayavka`)
- Футер (`footer.site-footer`)

### 4. Мобильная композиция
На 390px проверь:
- Шапку (header) — нет ли горизонтального скролла
- Навигацию и CTA-кнопки
- Калькулятор — читаемость карточек пакетов
- Форму заявки — все поля видны
- Футер — нет горизонтального переполнения

### 5. Проверка изображений
- Открой каждую секцию с изображениями
- Проверь, что все `<img>` загружены (не битые)
- Проверь `alt` атрибуты
- Проверь `loading="lazy"` на не-hero изображениях
- Проверь соотношение сторон (нет ли растянутых/сплюснутых)

### 6. Проверка галереи
- Открой главную галерею (10 фото)
- Нажми «Все фото» — проверь раскрытие полной галереи
- Открой лайтбокс на любом фото — проверь навигацию (‹ ›, Escape)
- Проверь, что `data-alt` соответствует `alt` в лайтбоксе

### 7. Проверка видео и модальных окон
- Нажми «Смотреть видео» в секции Ярмарка игр
- Проверь открытие модального окна
- Проверь, что видео загружается
- Закрой по крестику и по клику на фон
- Повтори для секции Площадка

### 8. Проверка типографики
- Заголовки h1–h2: читаемость, иерархия, контраст
- Текст: line-height ≥ 1.5, color не чистый белый на тёмном фоне (использовать rgba)
- Калькулятор: контраст текста на белом фоне шагов
- Кнопки: читаемость текста на `#C30067` и `#032E2B`

### 9. Проверка отступов и сеток
- Карточки в `format__grid`, `features__grid`, `reviews__grid`:
  - Равные отступы между карточками
  - Выравнивание по высоте
  - Нет наложения текста
- Галерея: сетка `gallery__grid` — равномерные ячейки
- Калькулятор: карточки пакетов — одинаковая высота

### 10. Проверка ошибок браузера
- Открой консоль браузера (инструмент просмотра console/log)
- Проверь, что нет ошибок (только предупреждения допустимы)
- Проверь сетевые запросы (инструмент просмотра network/логов)
- Убедись, что все ресурсы загружены (статус 200)
- Нет 404 на изображения, шрифты, скрипты
- Конкретные имена инструментов зависят от среды агента — используй
  доступные в ней средства браузерной автоматизации

### 11. Сохранение доказательств
- Все скриншоты сохрани в `docs/screenshots/`
- Именование: `{секция}-{разрешение}-{описание}.png`
  Пример: `hero-1440px-full.png`, `calc-390px-mobile.png`
- Скриншоты консоли ошибок: `console-errors-{date}.txt`
- Скриншоты сети: `network-{date}.txt`

### 12. Повторная проверка после исправлений
После любой правки, затрагивающей визуал:
1. Перезапусти dev server: `astro dev stop` → `astro dev --background`
2. Повтори скриншоты на проблемных разрешениях
3. Сравни с предыдущими скриншотами
4. Убедись, что исправлено и не сломано соседнее

## Ограничения
- НЕ меняй калькулятор, цены, состав пакетов без явного указания
- НЕ меняй тексты SPEC без явного указания
- НЕ коммить результаты аудита без разрешения
- При обнаружении критических визуальных багов — сообщить немедленно
