# 01-environment.md — окружение, команды, инструменты, деплой

## Стек

- Astro 7.4.2, Vite 8.3.5, Node ≥ 22.23.4 (фактически v24), TS strict.
- Без UI-фреймворков. Стили — чистый CSS внутри `.astro`.

## Команды

```bash
npm install              # установка зависимостей
astro dev --background   # dev-сервер в фоне (localhost:4321)
astro dev status         # статус фонового сервера
astro dev logs           # логи фонового сервера
astro dev stop           # остановка
npm run build            # production-сборка в ./dist/
npm run preview          # предпросмотр сборки
npm run astro check      # проверка типов (обязательна перед сдачей)
```

Dev-сервер держать в фоне, терминал не блокировать.
`astro check` — обязательный шаг верификации (04-verification.md).

## Инструменты агентов

- **Браузер**: встроенный browser_action (launch, click, type, press,
  scroll, resize, screenshot) — скриншоты и консоль в ответе на каждое
  действие. Альтернатива — Playwright MCP, если подключён в окружении
  (конфиг `.vscode/mcp.json` в проекте отсутствует; при подключении —
  дописать сюда).
- **npx**: есть (Node 24, npm 11). **lighthouse** глобально и локально
  не установлен — запускать через `npx --yes lighthouse <url>` по
  необходимости; установка в проект — решает Продюсер.
- **scripts/compress-images.js** — сжатие новых фото в public/photos/.
- **docs/screenshots/take-shots.cjs** — скрипт снимает скриншоты
  главного экрана по ширина́м; базовая линия «до» — docs/screenshots/.
- Скриншоты агентов сохранять в docs/qa/assets/ и
  docs/concepts/<дата>/ и т.п. (папка /screenshots/ в корне — артефакт
  браузерного инструмента, локально игнорируется git).

## Провайдер ИИ-моделей

- Степан пользуется агрегатором **aitunnel.ru**: OpenAI-совместимый
  шлюз ко многим моделям.
- Ключ — в `.env` под именем `AITUNNEL_API_KEY`. Никогда не в коде,
  коммите, чате, отчёте (Г5).
- Base URL — уточнить по документации/личному кабинету aitunnel.ru;
  обычно OpenAI-совместимый `https://api.aitunnel.ru/v1`.
- Список доступных моделей: `GET <base_url>/models` с ключом
  (например `curl -H "Authorization: Bearer $AITUNNEL_API_KEY"
  <base_url>/models`).
- Назначение: сильные модели для Продюсера/Эксперта (у Эксперта —
  производитель ДРУГОЙ, чем у Продюсера), генерация изображений для
  концептов. Генерация изображений пока не реализована — план, не
  строить без отдельной задачи от Продюсера.

## Деплой (гейт Г1)

- Локальный коммит — можно после всех проверок.
- Пуш/деплой на основной адрес — только по слову Степана («пуш»,
  «деплой», «выкладывай»).
- Preview-адреса Cloudflare Pages — разрешены автономно
  (одобрено Степаном 2026-11-04).
- Процесс: git push → Cloudflare Pages автодеплой → проверить
  https://xkalmar-party.pages.dev и preview-адрес.
- Хранит ли деплой ключи: Cloudflare Pages тянет окружение из своего
  дашборда, .env не коммитится.

## Доступы и ограничения (важно любому агенту)

- Расширение SourceCraft Code Assistant (форк Roo Code) скрывает от
  агентов всё, что перечислено в корневых .codeassistantignore,
  .gitignore, .arcignore (списки объединяются).
- Артефакты агентов (.playwright-mcp/, /screenshots/ в корне) скрыты
  от git через .git/info/exclude — локальный ignore, расширение его
  не читает: агенты файлы видят, git не коммитит. Не переносить их
  обратно в .gitignore.
- Скрытыми от агентов и git остаются: .env*, node_modules/, dist/,
  .astro/, логи, .DS_Store, .idea/, .gigacode_vsc/.
- Расширение просит подтверждение на запись в .roomodes, AGENTS.md,
  .vscode/** и файлы-игноры — это защита расширения, не обходить;
  Степан подтвердит кликом.
- Файл-игнор всегда скрывает сам себя — это не обходить.
- Режим Оркестратор по устройству режима не имеет инструментов чтения
  и записи файлов: управленческие задачи решает Продюсер (полный
  доступ), а не Оркестратор.
