> Проверка — в живом браузере, а не по скриншотам. Приёмку Степаном
> отменена: готовность подтверждает Дизайн-лид (против концепта) и
> отчёт Живого тестировщика без P0/P1. Пуш — только по слову Степана
> (Г1).

## Definition of Done (задача готова, когда всё выполнено)

1. **Контрольные цены** (если правка могла задеть калькулятор — Г4).
2. **Типы и сборка**: `npm run astro check` — 0 ошибок; перед коммитом
   в пуш — `npm run build` успешен.
3. **Консоль и сеть**: 0 ошибок в консоли главной; нет 404 на
   изображения, шрифты, скрипты.
4. **Восстановление состояния**: перезагрузка — sent-флаг, extSel,
   snapshot из localStorage (restoreCalcState) работают.
5. **Живой браузер** (skill xkalmar-visual-qa): клики, формы, модалки,
   галерея, анимации на 360/390/768/1024/1440; hover/focus/active/
   disabled. Скриншоты — доказательства для сравнения с концептом.
6. **Живой тестировщик**: отчёт docs/qa/live-<дата>.md без P0/P1
   (P2 — список Продюсеру на решение).
7. **Приёмка Дизайн-лида**: результат соответствует концепту
   (для визуальных задач), максимум 3 итерации.
8. **STATUS.md обновлён**: что сделано, скриншоты, вопросы Степану
   (если есть, пачкой ≤3 с дефолтами).
9. **Коммит локально** — можно; пуш — только по слову Степана.

## 1. Контрольные цены (процедура Г4)

Прогнать таблицу из SPEC-business.md «Контрольные цены» через
calculate(). Ключевые значения (полный список — в SPEC-business.md):
- popular 6 детей = 24 000 · popular 16 детей = 25 000
- optimal 6 = 33 500 · optimal 16 = 44 500
- maximal 6 всё включено = 50 000 · maximal 10 = 54 000 · снят торт = 43 000
- mini 5 = 15 000 · base 5 = 20 000
- extended 6 всё включено = 43 000
Не сходится — код не выдавать, искать причину; при противоречии —
запись в 06-registry.md и вопрос Степану пачкой с дефолтом.

## Техдолг-заметка

Если прогон контрольных цен можно автоматизировать скриптом — записать
идею в 06-registry.md (техдолг), в этой задаче не делать.
