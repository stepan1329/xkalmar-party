# 05-safety.md — запреты и опасные места

> Читать ПЕРЕД любой задачей. Нарушение пунктов «Гейты» — критическая
> ошибка (уровень 1).

## Гейты

1. Push/деплой — ТОЛЬКО по явной команде Степана («пуш», «деплой»,
   «выкладывай»). Локальный коммит после верификации — можно.
2. Задача не завершена без визуальной приёмки Степаном (скриншоты
   до/после + отчёт). Автопроверки необходимы, но недостаточны.
3. Правки калькулятора, цен, формул, текстов SPEC — только по явному
   заданию. Инициативная «оптимизация» цен запрещена.

## Не возвращать удалённое (сознательные решения прошлого)

- Правую колонку «Ваш тариф».
- Бар (заменён пиллом + шторкой).
- Absolute-бейджи, toprow.
- Опции «без ярмарки».
- Фиксированное «Банкет под ключ 6 000 ₽».

## Регрессионно-опасные места (правка = прогон контрольных цен)

- `calculate()` — единственный источник цен, формулы выверены.
- `pick()` / `pushSnapshot()` — перенос в форму; silent-режим.
- `restoreCalcState()` — восстановление из localStorage.
- `syncExt()` — ярмарка.
- `recalcAll()` — порядок синхронизации (syncProgramUI первой строкой).
- Слушатель `drcalc-refresh` — должен быть на document, НЕ на window
  (CustomEvent не всплывает; причина бага этапа А).
- Логика еды: единая формула для всех тарифов с едой (на 6 включено,
  сверх +1 000/чел). Никаких исключений для отдельных пакетов без
  прямого задания Степана.

## Модель поведения при конфликте

- Код/док против факта Степана → факт прав, фиксировать открытый вопрос
  (Правило №0 в AGENTS.md).
- Спорная инструкция в ТЗ → FIXME-REVIEW, не выдумывать компромисс.
- Противоречие SPEC vs ТЗ → решает Степан.
- Известный баг из 06-registry.md, помеченный «отложен» → не чинить
  самовольно.

## Чего не делать с документацией

- Не создавать новые md-файлы «на всякий случай» — карта файлов
  зафиксирована в AGENTS.md.
- Не переписывать факты SPEC-business.md — правит только Степан
  (или агент по его явному заданию).
- Артефакты ревизии хранить в plans/, мусор — удалять.
